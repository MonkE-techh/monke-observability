# What to set up by hand (and where)

These steps need your accounts, so only you can do them. Do them in order. The links are the pages as known on 2026-11-23; if one has moved, the step name tells you what to look for.

Never paste a **secret** (marked 🔒) into chat, code, issues or commit messages. Secrets go only into Render's environment settings.

## 1. PostHog project (EU)

1. Sign up or log in on the EU region: <https://eu.posthog.com/signup>
2. Create one project for all Monk-E apps (for example "Monk-E"). When asked which products to use, pick **Product Analytics, Web Analytics, Session Replay, AI observability, Logs**. Leave Error Tracking for later (the packages don't send to it yet) and skip the rest. Skip PostHog's install snippet: the monke-observability packages do the install.
3. Project settings: <https://eu.posthog.com/settings/project>
   - **Timezone:** Asia/Kolkata (peak-hour charts use it).
   - Copy the **Project token** (`phc_…`). Public; safe to share with me. Every app gets it as `POSTHOG_PROJECT_TOKEN` (backend) and `VITE_POSTHOG_PROJECT_TOKEN` (frontend).
   - Copy the **Project ID** (a number). The admin page gets it as `POSTHOG_PROJECT_ID`.
4. Billing limits, so there is never a surprise bill: <https://eu.posthog.com/organization/billing> — set a spending limit of $0 (or your choice) on each product.

## 2. PostHog personal API key for the admin page 🔒

1. <https://eu.posthog.com/settings/user-api-keys> → **Create personal API key**.
2. Scope: **Query → Read** only. Restrict it to the Monk-E project.
3. Put it straight into Render as `POSTHOG_PERSONAL_API_KEY` (step 5). Don't send it to me.

## 3. Google sign-in client for the admin page 🔒 (secret part)

1. Google Cloud console → Credentials: <https://console.cloud.google.com/apis/credentials> (use the Monk-E Google Cloud project; Engagement Bot Checker's project is fine).
2. If asked, set up the consent screen: user type **Internal** (only your Google Workspace accounts can sign in).
3. **Create credentials → OAuth client ID → Web application**, name "Monk-E admin".
4. **Authorised redirect URIs:**
   - `https://<your-admin-service>.onrender.com/api/auth/google/callback` (the Render URL from step 5; add it after the service exists)
   - `http://127.0.0.1:8000/api/auth/google/callback` (local testing, optional)
5. Copy the **Client ID** → `GOOGLE_CLIENT_ID` and the **Client secret** 🔒 → `GOOGLE_CLIENT_SECRET`.

## 4. GitHub repository

The public repo `MonkE-techh/monke-observability`. You approved me creating it with your GitHub login (`gh`); I'll ask once more right before pushing. To make it yourself instead: <https://github.com/organizations/MonkE-techh/repositories/new> (public, no README, no licence — the repo already has files).

## 5. Render service for the admin page

After the repo is on GitHub:

1. <https://dashboard.render.com/blueprints> → **New Blueprint Instance** → pick `MonkE-techh/monke-observability`. It reads `render.yaml` and creates the `monke-admin` web service (free plan, Singapore).
2. Fill in the values it asks for:

   | Variable | Value |
   |---|---|
   | `POSTHOG_PROJECT_ID` | from step 1 |
   | `POSTHOG_PERSONAL_API_KEY` 🔒 | from step 2 |
   | `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` 🔒 | from step 3 |
   | `ADMIN_EMAILS` | comma-separated Google accounts allowed in |
   | `GOOGLE_WORKSPACE_DOMAIN` | your Workspace domain (optional extra check) |
   | `PUBLIC_URL` | the service URL, e.g. `https://monke-admin.onrender.com` (no trailing slash) |

   `SESSION_SECRET` is generated by Render.
3. Add the service URL's callback to the Google client (step 3.4), then open the URL and sign in.

How Render environment variables work: <https://render.com/docs/configure-environment-variables>

### Keep it awake (free plan)

Render's free plan sleeps a service after 15 minutes without traffic, so the first load afterwards is slow.

1. UptimeRobot (free: 50 monitors, 5-minute checks): <https://uptimerobot.com/>
2. Add an **HTTP(s)** monitor for `https://<your-admin-service>.onrender.com/api/health`, every 5 minutes. That endpoint needs no sign-in and doesn't query PostHog.
3. Budget: free web services in one Render workspace share **750 hours a month**; one service awake all month uses about 720–744. If other free web services in the workspace need those hours, use the Starter plan for the admin page instead (change `plan:` in `render.yaml`).
4. Optional: add monitors for each app's health URL too, so you get an email when an app is down.

## 6. Each app (during the pilot and roll-out)

On every Render service of the app: `APP_NAME` (from `apps.yaml`), `APP_ENV=production`, `POSTHOG_PROJECT_TOKEN` (`phc_…`), `POSTHOG_HOST=https://eu.i.posthog.com`. Static frontends also need `VITE_POSTHOG_PROJECT_TOKEN` at build time. Code changes for each app are made in its own repo on a new branch.
